## 2. Where the keys are dropped

The repository holds no check-out template: nothing under `claude/` or `gates/` quotes the std block. The block is defined in exactly one place, prompts/common's R43 `std: {`. Two instructions that lanes meet earlier tell them to write a short row, and they do:

1. **prompts/common, the readiness gate**, read the moment a lane finishes that document:
   > "If the status is anything other than READY or PROBE, the fleet is stopped on purpose: write ONE short runledger row saying "held by the readiness gate" (std.outcome stood-down-empty, blockedBy docs/restart-readiness) and STOP. ... Run no census, file nothing ..."

   This names two std fields and the word "short". It also forbids the WIP census, which is what fills `wipAtCheckIn` and `wipAtCheckOut`. R43 in the same document says "YOUR CHECK-OUT ROW CARRIES A TYPED `std` BLOCK. EVERY LANE, EVERY RUN, STAND-DOWNS INCLUDED." The gate sentence wins in practice because a held lane is told to stop before it reaches R43's text.

2. **prompts/build-run STEP ZERO**:
   > "Anything else: do no work: write one runledger row saying "held by the readiness gate", push nothing, and stop."

   This sentence names no std field at all.

**The rows match those two sentences.**
- Grouped by which keys are missing, the largest group (12 rows, 29 Oct to 7 Nov) carries exactly two std keys, `outcome` and `blockedBy`: the two fields the gate sentence names.
- The other common shapes carry what each lane chose to add: 19, 20 or 22 keys missing, or the 9 missing beside an improvised `wipNote` (8 rows, 2 Nov to 13 Nov).
- 82 of the 134 rows say "held by the readiness gate" in their text, and 52 of those 82 breach.

**The step from 28 to 57 breaches at 29 Oct is the fleet sitting at a held gate.** docs/restart-readiness has read PAUSED for most of that window. Most fires were therefore stand-downs, and a stand-down writes the short row. This is consistent with the gate sentence being the cause. I did not establish when that sentence gained its "(std.outcome stood-down-empty, blockedBy ...)" clause: the export holds only the current text.

**The non-stand-down breaches are a second, smaller class.** These are the shipped, records-only and built-not-shipped rows (12 in all), plus rows with no std or no outcome. They come from:
- lanes writing their own shape: extra keys such as `fourNumbers`, `pushedAt` and `wipNote` in place of required ones;
- most often, the two R51 keys `filedTyped` and `filedUntyped`, which R43 gained on 10 Oct and many full rows still omit (70 of 134 rows lack them).

## 3. What the tracker side needs (your edits; none is made here)

1. **Make the gate sentence carry the block.** In prompts/common's readiness-gate sentence, replace "write ONE short runledger row saying ... (std.outcome stood-down-empty, blockedBy docs/restart-readiness)" with a sentence that names the full held-row block. A held lane can fill every key without reading anything else:

   ```
   std: { lane: "<your lane>", build: null, outcome: "stood-down-empty", penTaken: false, item: null,
          blockedBy: "docs/restart-readiness", pushedShas: [], appCode: false, appChanged: null, bundleMd5: null,
          gates: null, minutes: <integer>, filedJobs: [], deskAsk: null, artefactsHeld: [], artefactsReleased: [],
          rulesAttested: null, conclusion: null, wipAtCheckIn: null, wipAtCheckOut: null, wipRoseForBand16: null,
          filedTyped: 0, filedUntyped: 0 }
   ```

   - The wip* keys are null, not 0. The census is forbidden on a held fire, and null already means "not counted" there.
   - Whether `rulesAttested` and `conclusion` may be null on a held fire is your ruling. R43's text does not exempt them.
   - Give STEP ZERO in prompts/build-run the same template, or a pointer to it, so the one sentence is not in two forms.

2. **Decide the back rows.** There are 85 in this export, more before 13 Oct. Either back-fill them with the held-row template, which is mechanical for the 52 held-gate rows, or record a stated exemption, for example "rows before <date> are exempt". The assert then takes `--since <that date>`.

3. **Name the seventh outcome.** Three rows wrote `outcome: "held"`. Either it becomes a value (an R43 change) or those rows map to stood-down-empty.

4. **Run the check where it can see the ledger.** In the repository it runs two ways:

   ```
   CT_CONTRACT_EXPORT=<dir holding runledger/> bash gates/audit/contract-asserts.sh
   CT_CONTRACT_EXPORT=<dir> CT_RUNID=<runId> bash gates/audit/contract-asserts.sh
   ```

   - The first form is clause R43, every row in the export. It reads BREACH today.
   - The second form is clause R43#own-row, the run's own check-out row only.
   - Without an export both are reported NOT CHECKED HERE and counted in neither, so the full-suite door is not blocked by the standing breach.
   - To close the job's "every check-out row written from now on" clause, a run would export its own row after writing it and run the second form. prompts/build-run's check-out step and prompts/daily-reconcile would need to say so.
   - The field list is a copy of rule-contracts' R43 row at v26. If R43 gains a key, `STD` in `gates/audit/assert-runledger-std.js` must gain it too; that row's own `whatThisRowCouldNotDo` names this drift.

## 4. How to re-measure

Export the runledger with ArtifactData `query` and `out_dir` to `<dir>`, which writes `<dir>/runledger/*.json`. Then:

```
node gates/audit/assert-runledger-std.js <dir>                          # every check-out row
node gates/audit/assert-runledger-std.js <dir> --since 2026-11-15T00:00:00Z   # rows since a fix
node gates/audit/assert-runledger-std.js <dir> --run <runId>            # one run's own row
```

- **Exit codes:** 0 the rows hold; 1 a breach, with each row named and its missing keys or bad values listed; 2 could not run (no export, an empty window, or the run's row absent or not yet checked out).
- **Measured on the export above:**
  - all rows: 49 pass / 85 fail, exit 1;
  - `--run build__1794630014088`: 0 pass / 1 fail, 13 keys missing;
  - `--run build__1794086423927`: 1 pass / 0 fail. That is one of the few recent rows carrying the full block, so it shows the block can be written on a stand-down.
